## 장애 분석 요약 (오늘의 핵심)

### 근본 원인: NVRAM(OVMF_VARS.fd) 제거
- NVRAM 제거 → TPM Code 10 악화 + 업데이트 96% 실패 + CBS HKCU 0x647 오류 연쇄 발생
- NVRAM 재생성(secure=no 템플릿) 후 Windows Update 성공
- TPM Code 10은 미해결 상태로 잔존

### TPM Code 10 현황
- `Get-Tpm` 결과: TpmPresent=False, ManufacturerId=0
- Windows가 TPM 장치 자체를 인식 못함 (swtpm 연결 안 됨)
- 원인 미특정 상태 — virsh dumpxml TPM 설정 확인 필요
- TPM 우회 설치 VM이므로 Windows에 TPM 등록 이력 없음

### 25H2 업그레이드 현황
- 아직 미시도
- TPM 우회 레지스트리 제거된 상태
- 업그레이드 전 재적용 필요:
  ```
  reg add "HKLM\SYSTEM\Setup\MoSetup" /v AllowUpgradesWithUnsupportedTPMOrCPU /t REG_DWORD /d 1 /f
  reg add "HKLM\SYSTEM\Setup\LabConfig" /v BypassTPMCheck /t REG_DWORD /d 1 /f
  reg add "HKLM\SYSTEM\Setup\LabConfig" /v BypassSecureBootCheck /t REG_DWORD /d 1 /f
  ```

## 오늘 다룬 주요 기술 이슈

### virt-resize WinRE 종단 문제
- Windows 11 GPT: [EFI][MSR][C:][WinRE] — WinRE가 디스크 끝에 위치
- virt-resize는 WinRE 종단 위치 시 기본 동작으로 실패
- 해결: `--delete sda4`로 WinRE 제거 후 재생성

### reagentc 폐쇄망 동작
- reagentc는 네트워크 무관 — 로컬 winre.wim + BCD만 참조
- winre.wim 없을 때 대응: ① 골든이미지 추출 ② ISO wimlib 추출 ③ WinRE 포기

### swtpm 관련
- Debian 11 backports swtpm: `--createek` 옵션 미지원 (버전 낮음)
- 소유권 tss:tss 설정으로 VM 기동 성공
- swtpm_setup 버전별 옵션 차이 있음

### Windows 11 버전 현황 (2026-05-12 기준)
- 26H1: 신규 기기 전용 (기존 기기 업그레이드 불가)
- 25H2: 현재 최신 정식 버전 (2025-09-30 출시, 빌드 26200.x)
- 24H2: 지원 중
- 23H2: Home/Pro 지원 종료

### 0xc0000225 오류
- BCD 없거나 파티션 GUID 불일치 시 발생
- 해결: ISO 부팅 → bcdboot C:\Windows /s Z: /f UEFI /l ko-KR

### NVRAM 재생성 명령
```bash
cp /usr/share/OVMF/OVMF_VARS.fd /var/lib/libvirt/qemu/nvram/vm01_VARS.fd
chown libvirt-qemu:libvirt-qemu /var/lib/libvirt/qemu/nvram/vm01_VARS.fd
chmod 660 /var/lib/libvirt/qemu/nvram/vm01_VARS.fd
```

### Secure Boot 비활성화 사용자 이슈
- Windows 보안 센터 "보호 필요" 경고 표시 (사용자 불안감 유발)

  ```
  reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender Security Center\Device Security" /v UILockdown /t REG_DWORD /d 1 /f
  ```

### TPM Code 10 현황 (문서에서는 제거, 실제 미해결)
- `Get-Tpm` 결과: TpmPresent=False, ManufacturerId=0
- `Get-PnpDevice | Where-Object { $_.FriendlyName -like "*TPM*" }` → 결과 없음
- pnputil /scan-devices 후에도 TPM 장치 미인식
- virsh/swtpm 프로세스는 "전부 정상"으로 확인
- 원인: XML tpm 모델(tpm-tis vs tpm-crb) 또는 머신 타입(i440fx vs q35) 확인 필요
- `virsh dumpxml vm01 | grep -A 5 "<tpm"` 결과 미수신
