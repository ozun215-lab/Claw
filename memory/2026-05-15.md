## 미해결 이슈

### TPM Code 10
- 원인 가설: swtpm EK 미생성 또는 tpm-crb 모델 미설정
- 추가 가설 (2026-05-15): vTPM에 Secure Boot 키 미반영 → PCR[7] 미측정 → Code 10
- Code 10은 Secure Boot(secure=yes) 전환과 무관 — swtpm EK 재생성이 우선
- 확인 필요:
  - `swtpm --version`
  - `ls -la /var/lib/libvirt/swtpm/${UUID}/` (permall 파일 크기)
  - `virsh dumpxml vm01 | grep -A 8 "<tpm"` (tpm-crb 모델 확인)

### 25H2 업그레이드
- TPM bypass 레지스트리 적용 완료 (QEMU GA 경유)
- Code 10 해결 후 업그레이드 시도 예정

### secure=yes 전환
- 현재 최적 시점 (KB5078883 완료, 부트로더 최신화)
- Code 10 해결 후 별도 작업으로 진행 예정
- NVRAM → OVMF_VARS.ms.fd 교체만 필요 (loader는 이미 ms.fd)

## 주요 기술 결정 사항

### backing file과 NVRAM 상관관계
- NVRAM은 디스크 이미지와 완전 분리된 파일
- backing file 부트로더 버전 vs NVRAM DBX 충돌 → 99% 실패
- overlay 생성 시마다 NVRAM 별도 생성 필수
- 동일 NVRAM 공유 금지 (VM 간 부팅 항목 충돌)

### secure=no 영구 유지 시 이슈
- 폐쇄망 단기 운영: 실질 위험 낮음
- 중장기: DBX 격차 누적 → 향후 secure=yes 전환 비용 증가
- 실질 위험: 보안 센터 경고 노출, 내부자 물리 접근, 컴플라이언스
- 완화: UI 경고 숨김 레지스트리, KB5078883 이상 패치 유지

### OVMF_CODE.ms.fd
- Secure Boot 지원 펌웨어 (OVMF_CODE.secboot.fd와 동일 역할)
- secure=yes 전환 시 loader 변경 불필요

### Debian 11 backports swtpm
- 0.7.x 이상: `--create-ek-cert` 옵션 지원
- 0.5.x (기본): `--create-ek-cert` 없음, EK 수동 생성 필요
- EK 재생성: `swtpm_setup --tpm2 --create-ek-cert --lock-nvram --overwrite`
- 소유권: `chown -R tss:tss /var/lib/libvirt/swtpm/${UUID}`
