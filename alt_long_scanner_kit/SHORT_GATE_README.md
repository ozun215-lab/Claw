### 왜 이런 비대칭이 생기나 (해석)

- **BTC 4H < EMA200 구간에서는 롱·숏이 함께 진다** — 롱 −0.110R / 숏 −0.106R. 방향이 아니라 **양방향 휩쏘** 구간입니다.
- **BTC 4H > EMA200 구간에서는 롱(+0.054R)과 숏(+0.188R)이 함께 이긴다.** 상승장에서 알트가 무너지는 하향 이탈은 **상대 약세(로테이션 낙오)** 신호로 작동합니다. 반대로 위험회피 구간에서는 고베타 알트가 급반등해 숏이 스퀴즈됩니다.
- 따라서 숏의 "추세 정렬"은 하락 추세가 아니라 **시장 전체의 거래 가능성**을 뜻합니다. ATR ≥3%·거래량 ≥1.5×가 유효한 것도 같은 이유(변동성 = 기회)입니다.

## 적용 방법

숏 키트 내부를 고치지 않는 **독립 판정기**입니다. 키트 옆에 `short_regime_gate.py`를 두고 쓰십시오.

```bash
# 1) 라이브 판정 (현재 시장이 숏 가능한 국면인가)
python3 short_regime_gate.py --check --exchange okx --top 150

# 2) 스캐너 CSV에 게이트 컬럼 추가 (BLOCK / CAUTION / ALLOW + 포지션 배수)
python3 short_regime_gate.py --csv scan_rows.csv --out scan_rows_gated.csv

# 3) JSON (워크플로·대시보드 연동)
python3 short_regime_gate.py --check --json
```

파이썬에서 3줄:

```python
import short_regime_gate as G
v = G.verdict(G.market_state("okx", 150, 3_000_000))
print(v["action"], v["size"], v["reasons"])   # 예: ALLOW 1.0 ["브레드스 62% ≥ 50% ..."]
```

알림 파이프라인에 붙일 때는 `action == "BLOCK"` 이면 숏 알림을 **발송하지 않고**, `CAUTION` 이면 발송 문구에 포지션 축소를 명시하는 식으로 쓰면 됩니다.

## 반증 조건

1. 숏 게이트 적용 후 6개월 실전·페이퍼 승률이 34% 미만이거나 기대값이 마이너스면 규칙 1(BTC 필수)을 재검토합니다.
2. BTC 상단 구간의 숏 우위(+0.188R vs 하단 −0.106R)가 신규 데이터에서 0.05R 이내로 좁혀지면 이 비대칭 가설은 폐기합니다.
3. 선호 조건(거래량 ≥1.5×)의 우위가 표본 300건 이상에서 사라지면 선호 조건을 제거합니다.
